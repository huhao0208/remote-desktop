## 二、逐项技术拆解：自己实现要什么

### 1. 自定义码率（最高 500Mbps）
- **技术本质**：编码器 bitrate 参数上限。不是技术门槛，是产品策略。
- **实现成本**：★☆☆☆☆（一行参数）
- **自研建议**：直接开放 0.5–50 Mbps 滑块；500Mbps 需要 10G 网络才有意义，家用场景 50M 足够。
- **注意**：真实瓶颈是上行带宽和编码器性能，不是软件限制。

### 2. 原画画质
- **技术本质**：不缩放采集源，按原始分辨率编码。
- **实现成本**：★☆☆☆☆（去掉 resize）
- **自研建议**：默认就传原始分辨率。注意 4K 屏 + 60fps + 原画 ≈ 30–60 Mbps 上行压力。

### 3. 144 帧率
- **技术本质**：采集/编码/渲染/显示全链路支持 144Hz。
- **实现成本**：★★☆☆☆
- **关键约束**：
  - 被控端显示器必须 ≥144Hz
  - 编码器要能 144fps 实时编码（硬编一般可以）
  - 传输带宽 ≈ 帧率 × 单帧大小，144fps 比 60fps 带宽 ×2.4
  - 控制端窗口也要 144Hz 刷新
- **自研建议**：先做 60，稳定后开放 90/120；144 收益边际小、成本高。

### 4. 真彩（True Color）
- **技术本质**：色度采样 4:4:4（而非 4:2:0），色深 8bit 全保留。
- **实现成本**：★★★☆☆
- **约束**（官方文案已说明）：
  - 与 **HDR 互斥**
  - 需要硬解（软解撑不住）
  - 带宽约 ×1.5–2
  - 部分画质档位不支持（「真彩模式不支持所设画质」）
- **自研建议**：H.264 4:4:4 支持差，建议用 **H.265 4:4:4** 或直接上 **AV1**。优先级低。

### 5. HDR
- **技术本质**：HDR10 / HLG 元数据传递 + 10bit 色深 + PQ/HLG 色调映射。
- **实现成本**：★★★★★（最高）
- **链路要求**：被控端 HDR 采集 → 10bit 编码 → HDR 元数据透传 → 控制端 HDR 显示 → 控制端屏幕支持 HDR
- **自研建议**：**不建议做**。链路太长，任何一环不支持就降级，收益极小。

### 6. 超级屏
- **技术本质**：创建一块高规格虚拟显示器，把物理屏关掉，所有内容渲染到虚拟屏。
- **实现成本**：★★★★☆
- **依赖**：虚拟显示器驱动（Windows `IDD` / macOS `CGVirtualDisplay`）
- **自研建议**：和虚拟屏共用一套底层能力，先做虚拟屏，超级屏是它的"高配模式"。

### 7. 虚拟屏
- **技术本质**：向系统注册一块虚拟显示器。
- **实现成本**：★★★★☆
- **平台差异**：
  - Windows：需写 **IDD 驱动**（KMDF + WDF，需签名）或调用 `SetDisplayConfig` 配合已有虚拟屏驱动
  - macOS：`CGVirtualDisplay` 是**私有 API**（需特殊手段调用），或用 `ScreenCaptureKit` 的虚拟显示能力（macOS 14+）
  - Linux：X11 用 `Xvfb`，Wayland 需 `wlroots` 虚拟输出
- **自研建议**：**短期跳过**。这是整套方案里工程成本最高的一块（驱动 + 签名 + 兼容性）。

### 8. 多显示器 / 多窗口
- **技术本质**：多路视频轨道 + 多窗口管理。
- **实现成本**：★★☆☆☆
- **你的优势**：`StreamerManager` 的 `videoTrackIndex` 已证明官方就是多轨道；你的 Electron 天然支持多 `BrowserWindow`。
- **自研建议**：**优先做**。成本低、体验提升明显。agent 侧 `mss.monitors` 已能枚举多屏。

### 9. 多主控端同时远控
- **技术本质**：一个被控端接受多个控制端连接，广播媒体流（或分别编码）。
- **实现成本**：★★★☆☆
- **架构选择**：
  - 方案 A：被控端编码一次，多路分发（省 CPU，但码率要按最差网络适配）
  - 方案 B：每个控制端独立编码（体验好，CPU ×N）
- **自研建议**：先做 A（单编码多分发），信令层加 `room.participants` 数组。

### 10. 隐私增强（熄屏）
- **技术本质**：物理关闭被控端显示器输出，画面只进虚拟屏。
- **实现成本**：★★★☆☆
- **依赖**：虚拟屏（否则关屏就抓不到画面了）
- **替代方案**（不依赖虚拟屏）：亮度降到 0 + 全屏黑窗覆盖（防护弱，但成本极低）
- **自研建议**：先做"黑窗覆盖"，虚拟屏就绪后再升级熄屏。

### 11. 隐私屏保
- **技术本质**：全屏置顶图片覆盖物理屏。
- **实现成本**：★☆☆☆☆
- **实现**：
  - Python agent：`tkinter` 全屏 `topmost` 窗口显示图片
  - Electron：`BrowserWindow({fullscreen, alwaysOnTop, skipTaskbar})`
  - Windows 可用 `SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)` 让覆盖窗不被自己捕获
- **自研建议**：**优先做**，成本极低（半天），安全感知强。

### 12. 安全中转通道
- **技术本质**：TURN/中继服务器兜底。
- **实现成本**：★★☆☆☆
- **现状**：你已经有 coturn 部署（`3478 + 49160-49200/udp`），**这项你已经免费实现了**。
- **自研建议**：保持即可；可加"直连优先、中转兜底"的自动切换 + UI 标识（官方有「局域网直连 / 安全中转连接」两个状态）。

### 13. 文件高速中转
- **技术本质**：文件走中继通道时的带宽提升（官方用语"升级中转传输通道"）。
- **实现成本**：★☆☆☆☆（你已有 TURN，只是带宽策略）
- **自研建议**：不设限，按服务器带宽自然限制。

### 14. 手柄直连
- **技术本质**：手柄输入透传到被控端（非按键映射，而是虚拟手柄设备）。
- **实现成本**：★★★☆☆
- **链路**：控制端读手柄 → 事件传输 → 被控端创建**虚拟手柄设备**（Windows 需 `ViGEmBus` 驱动；macOS 用 `IOHIDUserDevice`）
- **官方证据**：`GCSupportedGameControllers: ExtendedGamepad`、`device_gamepad`、`GamePad.backKey1-4`
- **自研建议**：中等成本。先用"手柄→键鼠映射"（成本 ★☆☆☆☆），需要真手柄体验再上 ViGEmBus。

### 15. 无线副屏
- **技术本质**：移动设备当被控端的扩展屏（反向：本机屏幕扩展到手机/平板）。
- **实现成本**：★★★☆☆
- **链路**：被控端创建虚拟屏 → 画面推到移动端 → 移动端触摸事件回传 → 注入为虚拟屏的输入
- **依赖**：虚拟屏（同 #7）+ 移动端触摸注入
- **自研建议**：依赖虚拟屏，**延后**。

### 16. 观看模式
- **技术本质**：只渲染不发送输入事件。
- **实现成本**：★☆☆☆☆（一个 boolean）
- **自研建议**：**立刻做**。一行开关，安全价值高（防误触）。

### 17. 屏幕墙（多设备监控）
- **技术本质**：同时拉多路低码率流，网格布局。
- **实现成本**：★★☆☆☆
- **自研建议**：需要多路解码能力。WebCodecs 可以并行解码多路；先用低分辨率缩略流（5fps）降低成本。

### 18. 全球远控（跨境）
- **技术本质**：海外节点 + 稳定跨境链路。
- **实现成本**：★★★★☆（成本在基础设施，不在代码）
- **自研建议**：个人自用不需要；真要做得有海外 VPS + 智能路由。

| 难度 | 项数 | 能力 |
|---|---|---|
| ★☆☆☆☆ 极低（半天内） | 5 | 自定义码率、原画画质、隐私屏保、观看模式、文件高速中转 |

## 四、自研产品该怎么设计（不给限制的建议）

既然你不做商业化，不需要会员墙，建议这样组织：

### 4.1 不设"功能墙"，设"能力自检"
```
应用启动 → 探测本机能力 →
  ├─ 硬编支持？ → 是：默认硬编，否：软编 + 提示
  ├─ 屏幕 HDR？ → 是：显示 HDR 开关，否：置灰 + 说明
  ├─ 上行带宽？ → 实测后推荐码率上限
  └─ 生成能力矩阵 → 只在"真的做不到"时置灰，不因付费置灰
```

### 4.2 用"质量档位"替代"付费档位"
官方：省流 / 高清 / 超清 / 蓝光 / 原画（后两档付费）
自研：全部开放，但给出**带宽预估**提示

```
画质： 省流(≈1M) | 高清(≈4M) | 超清(≈8M) | 原画(≈20M+)
提示： "原画需要约 20Mbps 上行，当前网络实测 8Mbps"
```

### 4.3 不做的能力用"诚实置灰"
- HDR 不支持 → 置灰 + tooltip「当前链路不支持 HDR（需 10bit 编码 + HDR 显示器）」
- 虚拟屏未实现 → 置灰 + tooltip「虚拟屏需要显示驱动，当前版本未支持」
- **不要**出现"开通会员"字样

### 4.4 免费开放优先级（按 ROI）
```
第 1 批（立刻，半天）：观看模式、隐私屏保、自定义码率、原画画质
第 2 批（本周）：多显示器多窗口、安全中转（已有）
第 3 批（下周）：144 帧率、多主控端、屏幕墙
第 4 批（视需要）：真彩、手柄直连（键鼠映射先行）
第 5 批（暂缓）：隐私熄屏、超级屏、虚拟屏、无线副屏、HDR
```
