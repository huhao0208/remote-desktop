# 媒体链路实测（JPEG vs H.264）

> 用途：给「画质该定多少码率」提供数据依据，避免拍脑袋。
> 相关：`docs/media-protocol.md`（媒体契约）、`HANDOFF.md` ADR-8（为什么改 WebRTC）
> 状态：本机单次实测，2026-11-20

---

## 1. 一句话结论

**H.264 8 Mbps 的画质（PSNR 45.77 dB）明显高于旧「高清档」JPEG（37.16 dB），而每帧只有后者的 1/6、带宽只有 1/3.5。**
换句话说：换成 WebRTC + H.264 不是「用画质换带宽」，是**两头都赢**。

---

## 2. 实测数据

| 方案 | PSNR | 每帧大小 | 带宽 |
|---|---|---|---|
| 旧默认 JPEG 1280/q55 | 26.90 dB | 90 KB | 11.0 Mbps @15fps |
| 旧高清 JPEG 1920/q75 | 37.16 dB | 231 KB | 28.4 Mbps @15fps |
| **H.264 4 Mbps** | 39.73 dB | 23 KB | 4 Mbps（编码目标） |
| **H.264 8 Mbps** | **45.77 dB** | 38 KB | 8 Mbps（编码目标） |
| H.264 20 Mbps | 48.48 dB | 69 KB | 20 Mbps（编码目标） |

> 注 1：JPEG 两行的带宽是按 **15fps** 折算的；H.264 行给出的是编码器目标码率（实测码率随画面内容浮动，每帧大小为实测均值）。
> 注 2：H.264 是 4:2:0，色彩细节的理论上限约 50 dB，所以 20 Mbps 相对 8 Mbps 的收益已经很薄（+2.7 dB 换 2.5 倍带宽）。

### 2.1 怎么看这张表

| 对比 | 差值 | 读法 |
|---|---|---|
| JPEG 1280/q55 → JPEG 1920/q75 | +10.3 dB | 加分辨率+画质，代价是带宽 ×2.6（11 → 28.4 Mbps）——这就是旧链路的困境：想清楚就吃满带宽 |
| JPEG 1920/q75 → H.264 4 Mbps | +2.6 dB | **画质更好，带宽只有 1/7** |
| JPEG 1920/q75 → H.264 8 Mbps | +8.6 dB | 带宽 1/3.5，画质接近视觉无损 → **默认档选 8 Mbps** |
| H.264 8 → 20 Mbps | +2.7 dB | 边际收益低，留给「同城/专线」档 |

## 3. 测试方法

1. **取图**：`mss` 抓本机真实屏幕，原始 2048×1280（真实桌面内容，不是测试图；避免纯色/渐变图让 PSNR 虚高）。
2. **基准**：统一缩到 1920 宽作为参考图（ref），所有方案的 PSNR 都与它比较——保证不同方案比的是「同一帧的还原度」。
3. **JPEG 通路**：Pillow 编码（`subsampling=2`，4:2:0），quality 与宽度按表中标注；解码后与 ref 算 PSNR。
4. **H.264 通路**：PyAV 调 libx264 做**编解码往返**（encode → decode），参数：
   - `preset=ultrafast`
   - `tune=zerolatency`
   - `bframes=0`
   - 码率按表中设定（4 / 8 / 20 Mbps）
5. **度量**：解码帧与 ref 逐像素算 PSNR（dB）。
6. **每帧大小**：编码输出字节数，多次取均值。

> 口径说明：这测的是**编码器还原度**，不含网络传输与渲染环节。真实体验还受 RTT、丢包、抖动缓冲影响——所以 `docs/media-protocol.md` §7 的验收项必须在真机上跑，不能只靠 PSNR。

## 4. 由数据得出的参数（已写进契约）

| 参数 | 值 | 依据 |
|---|---|---|
| 默认码率 | **8 Mbps** | 45.77 dB，接近 4:2:0 上限，带宽仍是旧高清档 1/3.5 |
| 流畅档 | 4 Mbps | 39.73 dB，仍优于旧「高清」JPEG（37.16 dB） |
| 超清档 | 20 Mbps | 48.48 dB，只对同城/专线有意义 |
| 默认分辨率 | 1920 宽（屏幕更窄时取原宽） | 不做超采样，保持 1:1 像素 |
| 降级偏好 | `maintain-resolution` | 数据证明「分辨率」对 PSNR 的贡献远大于「码率微调」（见 2.1 第一行），宁可掉帧 |

---

## 5. 局限（别过度解读）

- 单机、单次、单场景（桌面静态内容为主）。动态内容（视频/滚动）下 PSNR 会下降，且 H.264 的优势会变化（帧间预测在静止画面上收益最大）。
- PSNR 与主观观感不是线性关系：40 dB 以上人眼差异已不明显，**45.77 dB 可以说是「肉眼无损」**；但文字边缘的锐度更看编码器细节保留能力，仍需真机目视确认。
- 未测 4:4:4、未测 H.265/AV1、未测硬编（VideoToolbox/NVENC）。若后续上硬编，需重测——硬编在低码率下的画质通常不如 x264 ultrafast。
- 未测网络路径，延迟/丢包恢复能力**不能**用这份数据推断。
